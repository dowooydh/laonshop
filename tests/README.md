# LAON SHOP QA 운영 구조

이 폴더는 Codex QA/테스트 담당 세션의 작업 공간이다. 제품 코드는 사용자가 명시적으로 허락하기 전까지 수정하지 않고, 테스트 시나리오, 실행 기록, 리뷰 결과, 재현 문서만 이곳에 남긴다.

## 현재 구성

- `inventory/`: 프로젝트 구조, 기능 목록, 테스트 대상 분석
- `checklists/`: 수동/E2E/회귀 테스트 체크리스트
- `data/`: 테스트 데이터 정책, 정리 기준, 금지 작업
- `handoff/`: 최신 QA 결과와 개발 세션 전달 문서
- `environment.md`: 로컬 테스트 환경, 환경변수, 셋업 순서
- `e2e/`: 향후 Playwright 등 E2E 테스트 코드 위치
- `api/`: 향후 API/서버 액션/PG 콜백 테스트 코드 위치
- `reports/`: 실행별 원본 로그, 스크린샷, 증적 위치

## QA 원칙

1. 실제 사용자 관점으로 흐름을 검증한다.
2. 카드사 심사 필수 요건을 별도 축으로 관리한다.
3. 결제 금액은 DB/서버 기준으로 검증하고, 클라이언트 장바구니 금액은 신뢰하지 않는다.
4. 카드정보, PG 키, 세션 시크릿, 운영 마스터 데이터는 테스트 산출물에 남기지 않는다.
5. 결함을 발견하면 제품 코드 수정 대신 재현 경로, 원인 추정, 관련 파일, 우선순위를 `handoff/latest.md`에 정리한다.

## 테스트 요청 시 기본 절차

1. 최근 변경사항 확인: `git status`, `git diff`, 필요 시 최근 커밋 비교
2. 환경 확인: Node 22.x, pnpm 11.5.3, 테스터 전용 Neon 브랜치, 로컬 `SHOP_APP_URL`
3. 영향 범위 분석: 라우트, 서버 액션, DB 모델, PG 경계, UI 흐름
4. 시나리오 선정: happy path, 취소/뒤로가기, 중복 요청, 권한, 빈 상태, 에러 상태, 모바일
5. 실행 및 증적 수집: 브라우저, API, DB 확인, 콘솔/서버 로그 확인
6. 정리: 테스트 데이터 청소 원칙 준수, `handoff/latest.md` 갱신

## 보안·통합 QA 기준 (2026-11-06)

현재 기본 게이트는 [security-audit.md](security-audit.md)에 정의한다. `node scripts/qa/full.mjs`는 자격정보 없는 소스·의존성·비밀값 검사, QA 실행기 자체 시험, 전용 격리 환경의 제품 test·lint·typecheck·production build·HTTP/브라우저 검사를 묶는다. 기본 QA와 선택 PentAGI·Cloudflare 감사의 결과를 구분하고, 시작·종료 SHA·검사 누락·정리 실패를 확인한다.

QA 담당은 정확한 제품 SHA·수용 조건·DEV 결과를 인계받고 독립 결과를 기록한다. DEV 자체 검사와 독립 소스 검토·실행 QA는 서로 다른 증거다. 과거 Neon 브랜치 지침이 현재 격리 실행을 운영 DB에 연결할 근거가 되지는 않는다. 신규 보안 검증은 운영 자격정보 없는 폐기 가능한 로컬 PostgreSQL만 사용한다.
